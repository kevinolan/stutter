# Stutter-Detection Training & Fine-Tuning

This folder trains and fine-tunes a stutter-speech classifier using **librosa**
(feature extraction) and **torchaudio** (model + training). Two model paths are
provided:

| Model | Input | Notes |
| --- | --- | --- |
| `cnn` (default) | librosa log-Mel (3 × 64 × 128, with delta/delta²) | Fast baseline, CPU-friendly |
| `wav2vec2` | raw 16 kHz waveform | Fine-tunes `torchaudio` Wav2Vec2 base |

> ⚠️ The bundled dataset is **synthetic** (generated by `generate_data.py`) and
> exists only to verify the pipeline runs end-to-end. It is **not** clinical data.
> Replace `training/data/<split>/metadata.csv` (rows `file,label` where label 1 =
> contains stutter) with a real corpus (e.g. UCLASS, FluencyBank, KCL) to train a
> usable model.

## Setup

```bash
cd stammer
uv venv .venv
uv pip install --python .venv -r training/requirements.txt
uv pip install --python .venv onnx onnxruntime onnxscript   # for ONNX export
```

## Run

```bash
# Generate the synthetic dataset (first run, or to refresh)
.venv/Scripts/python.exe training/generate_data.py

# Smoke test: datasets + both models build and pass a forward pass
.venv/Scripts/python.exe training/smoke_test.py

# Train the CNN baseline (saves checkpoints/cnn_best.pt + metrics.json)
.venv/Scripts/python.exe training/train.py --model cnn --epochs 8

# Fine-tune Wav2Vec2 (downloads ~360MB pretrained checkpoint on first run)
.venv/Scripts/python.exe training/train.py --model wav2vec2 --epochs 4

# Resume / continue fine-tuning from a checkpoint
.venv/Scripts/python.exe training/train.py --model cnn --resume training/checkpoints/cnn_best.pt

# Score an audio file
.venv/Scripts/python.exe training/infer.py training/checkpoints/cnn_best.pt path/to/audio.wav
```

## Export to ONNX (for the web app)

`export_onnx_featured.py` builds a single ONNX graph that takes **raw 16 kHz mono
PCM** and internally performs the exact librosa feature extraction (log-Mel + deltas)
the model was trained on, then runs the CNN. PyTorch vs ONNX logit diff is < 1e-6.

```bash
.venv/Scripts/python.exe training/export_onnx_featured.py
# -> training/onnx/cnn_stutter_pcm.onnx  (copy into speech-therapy-app/public/models/)
```

The React app (`speech-therapy-app`) loads `cnn_stutter_pcm.onnx` via
`onnxruntime-web` and scores each recording fully on-device — no servers, no keys.

## Use a REAL corpus

1. Obtain a licensed corpus (UCLASS requires a data-request form — see
   `download_uclass.py`). Lay it out as `fluent/` + `stutter/` (or a `labels.csv`
   with `path,label`).
2. Resample + emit the metadata the trainer expects:

   ```bash
   .venv/Scripts/python.exe training/prepare_real_corpus.py \
       --in_root /path/to/corpus --out_root training/data/real
   ```

3. Train on the real data (more epochs / larger batch — needs a real corpus + ideally GPU):

   ```bash
   .venv/Scripts/python.exe training/train.py --data_root training/data/real \
       --model cnn --epochs 40 --batch-size 32
   ```

4. Re-export to ONNX and copy into the app.

## Files

- `generate_data.py` — synthetic dataset generator (librosa-free; uses `soundfile`)
- `dataset.py` — `StutterDataset` (librosa mel features) + `RawStutterDataset` (waveforms)
- `models.py` — `StutterCNN`, `Wav2Vec2StutterClassifier`, `build_model()`
- `train.py` — training / fine-tuning driver (BCE loss, AdamW, best-checkpoint saving)
- `infer.py` — load a checkpoint and score one audio file
- `smoke_test.py` — pipeline self-check
- `export_onnx_featured.py` — export the CNN + librosa frontend to ONNX (raw PCM in)
- `prepare_real_corpus.py` — resample a real corpus to the trainer's `file,label` format
- `download_uclass.py` — UCLASS data-request + prep scaffold (no auto-download; license-gated)
- `dump_reference.py` / `dump_melfb.py` — parity/debug helpers

## Notes

- Audio I/O uses `soundfile` (a librosa dependency) because `torchaudio.save` in
  this environment requires the optional `torchcodec` package.
- Synthetic data is deliberately separable, so the CNN hits ~100% val accuracy
  quickly — that measures **pipeline correctness**, not real-world performance.
- Wav2Vec2 learns speaker/linguistic structure from raw audio and needs a large
  real corpus + GPU epochs to beat chance; on the 160-clip synthetic set it stays
  near 0.5 (and that is expected, not a bug). The fine-tune loop itself is verified.
